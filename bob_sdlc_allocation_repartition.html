Guardrails par phase — à configurer dans .bobrules
Modernisation
Human checkpoint toutes les 3 modifications de fichier. Auto-rollback interdit. Aucun merge automatique. Données synthétiques uniquement dans le contexte.
Coding
Orchestrator bloqué par défaut (spending cap user). Code mode limité aux repos de l'entité déclarée. Pas d'accès aux repos d'autres entités sans approbation IT Central.
CI/CD Shell
Bob Shell uniquement en mode --no-interactive. Pas d'écriture sur le repo en pipeline. Output = rapport uniquement (risk score, PR summary, SAST findings).
SAST / Sécu
Findings CRITICAL et HIGH → commentaire bloquant sur la PR. Fix suggéré par Bob mais appliqué uniquement après validation security engineer. Ne pas auto-closer les findings.
Compliance
Aucune donnée Bâle IV, DORA, ACPR réelle dans le contexte Bob. Templates uniquement avec placeholders. Tout output passe par le Risk Committee avant diffusion.
Toutes phases
.bobignore configuré sur : credentials/, secrets/, *.env, data/production/**, scoring-models/**. Pas d'accès aux fichiers de configuration de production.
Structure .bobrules globale recommandée
# .bobrules — BNP Paribas global guardrails
# Chargé automatiquement par Bob dans tous les modes

## Data residency
- Never include real customer data, IBAN, account numbers in prompts
- Never read files matching: credentials/**, *.env, data/prod/**
- Scoring models are off-limits: scoring-models/**

## Code safety  
- Always request human approval before modifying more than 3 files
- Never auto-commit or auto-merge generated code
- Flag BigDecimal violations (float/double for monetary amounts)

## Mode restrictions
- Orchestrator requires explicit user confirmation per session
- CI pipeline (Bob Shell): --no-interactive flag mandatory
- SAST findings CRITICAL/HIGH block PR merge

## Audit
- All Bob sessions must be traceable to a JIRA ticket
- Generated code must carry @bob-generated comment header
